# DeepSeek V4 Vision experimental support: local correctness review

Reviewed `f4d6c4f2..a39d758a` (foundation, original checkpoint loading, TP2 serving,
and optional performance paths). Fixes are working-tree changes on `a39d758a`.
The review targets runtime failures and incorrect results; it does not qualify
the experimental model or claim a performance improvement. ATC coordination was
explicitly waived by the user for this local task.

## Findings fixed

| Priority | Trigger and defect | Correction and evidence |
| --- | --- | --- |
| P1 | Batched round staging used a byte offset to slice an `i32` array, panicking before execution. | Use the element offset. The production staging regression failed before the fix with `start index 128 is larger than end index 40`; it now passes with padding and partially sampled rows. |
| P1 | Batched row heads copied logits back into the single-row scratch buffer rather than the collective send buffer. The gathered result read unwritten data, and later rows could exceed scratch capacity. | Copy each row into `rb.exch`. A host-backed production-path regression checks both ranks' logits and scratch preservation. Restoring the old line reproduces an aliasing failure at row zero. |
| P1 | FP8 gather compacted selected cache rows, but sparse attention indexed the compact buffer with original cache addresses, selecting wrong or out-of-bounds rows. This affected target and draft attention. | A shared launch helper uses original IDs for gather and linear IDs for attention. Host launch-argument checks and actual CUDA gather/attention comparisons cover noncontiguous and partial-draft selections. |
| P1 | FP8 staging was sized for top-k selection only. Ratio-128 layers at a 262144-token context select 2176 rows, exceeding the former 1024-row allocation. | Size staging for the largest compressed selection, image/window rows and draft block; validate launch capacity. A host sizing test and a 2176-row GPU case pass. |
| P1 | `Graphs.init` returned a structure whose cache callback retained the address of its temporary local engine. A later callback could dereference expired stack storage. | Initialize the graph owner in place. The production initializer address regression failed before the change and passes afterward. |
| P1 | Multirow prefill was marked graphable although graph execution validates every row against a sequence length advanced only after the round. The second row failed with `PositionMismatch`. | Keep multirow segments on the ordinary eager batched path. The planner regression preserves batching while refusing graph replay for this shape. |
| P1 | TP2 execution identities omitted draft startup, graph execution and transport modes. Different settings could pass identity validation and then issue incompatible collective/control sequences. | Include these modes and graph scheduling parameters in the identity. Regression tests distinguish mismatched modes, graph row limits and retention policy. |
| P1 | Reading a parked transport/control frame cleared its length before constructing the returned slice, so the caller received an empty frame. | Preserve the length through copying and return. A regression also verifies a short receive buffer does not consume the pending frame. |
| P2 | Serving unconditionally enabled the page-layout planner, bypassing `TF_DSV4_KV_PAGES` and changing default memory planning. | Call the existing gated `layoutOf` helper. |
| P2 | A failed startup timing pass leaked its temporary sequence slot, reducing the serving pool. | Release the slot on every exit from each measurement width. An injected forward failure regression passes. |
| P2 | The fake golden server still called the pre-change `HfText.load` signature, blocking compilation of `test-golden`. | Supply the new optional chat argument; both golden corpora complete without unexpected differences. |

The allocation failure path also frees the sequence journal if FP8 staging
allocation fails. The graph memory probe now returns unavailable on non-Linux
hosts, allowing the production initializer regression to compile on Windows.

## Validation

Environment: Windows x86_64, pinned Zig 0.17.0, NVIDIA RTX 5070 Ti (16 GiB),
CUDA toolkit 13.1, `sm_120`. No checkpoint was loaded and no model server was
running for the GPU checks. The CUDA kernel sources were not changed.

All commands below exited zero on the corrected tree:

```text
zig build test test-kernel-contract test-golden fuzz-cortheon --summary all
zig build --summary all
zig build test-dsv4-vision test-dsv4-text test-dsv4-cluster test-dsv4-cuda-host test-release-cuda-refusal-host --summary all
zig build compile-config-server check-dsv4-target dsv4-worker dsv4-verify -Dtarget=x86_64-linux-gnu --summary all
git diff --check
```

- Complete host/golden/fuzz invocation: 292/292 build steps succeeded. The final
  invocation executed 324 passing tests and skipped 6; other successful steps
  were cached from the earlier full run (3102 passed, 57 skipped, with only the
  subsequently corrected golden-server compilation failure).
- Golden corpus: 303/315 equal, 12 existing known differences, zero unexpected
  differences. Secondary corpus: 26/26 equal.
- Plain build: 22/22 steps succeeded.
- Focused family/CUDA-host checks: 17/17 steps succeeded, 388 passing tests and
  5 skipped before adding the graph-owner regression. The final vision suite
  includes that regression and passes 117/117 tests.
- Linux server, worker, verifier and target checks: 15/15 steps succeeded.
  These are cross-compilation results, not Linux execution results.
- Lean comparison against `a39d758a`: 442 inherited findings in each tree,
  zero new findings. The baseline is not clean.

The new `tools/dsv4-vision/check_kv8_cuda.py` runs the existing CUDA gather and
sparse-attention kernels, checks decoded BF16 rows exactly, and compares
attention with an independently computed FP64 reference. Reproduce with:

```text
nvcc --fatbin -arch=sm_120 zig/kernels/cuda/dsv4_text.cu -o dsv4_text.fatbin
nvcc --fatbin -arch=sm_120 zig/kernels/cuda/dsv4_ops.cu -o dsv4_ops.fatbin
python tools/dsv4-vision/check_kv8_cuda.py dsv4_text.fatbin dsv4_ops.fatbin --report kv8-gpu.json
```

On Windows, supply the installed MSVC compiler directory through `-ccbin` if
needed. The Python harness requires NumPy. Results: 3 passed, 0 failed, with
five byte-identical attention repeats per case and unchanged input/guard rows.
The JSON report retains worst per-column errors.

## Remaining validation limits

No two-Spark TP2/NCCL, P2P/RoCE, complete model checkpoint, served generation,
draft/plain token equality, cache-resume equality, or real CUDA graph replay
was executed. No Metal or alternate GPU architecture was tested. The GPU
microchecks and host regressions do not substitute for these gates. No
throughput, cold-prefill or memory-fit claim is made. The next integration gate
is an actual two-Spark checkpoint run covering batched eager/graph decode and
BF16/FP8 target/draft execution, including concurrency and resumed requests.
